# ADR-006: Сделка как объект диаграммы состояний

## Контекст и постановка задачи
Жизненный цикл сделки явно определён в SRS и влияет на доступность отзывов и операции TC. Для какой сущности строить State Machine Diagram?

## Драйверы решения
- Явный жизненный цикл в SRS.
- Состояние сделки ограничивает допустимые действия.
- Связь статуса с отзывами и операциями TC.
- Недопустимые переходы должны отклоняться.

## Рассмотренные варианты
- Диаграмма состояний для `Deal`.
- Диаграмма состояний для `Review`.
- Диаграмма состояний для запроса верификации.

## Итог решения
Выбрана **State Machine Diagram для `Deal`** со статусами `Created`, `In progress`, `Completed`, `Cancelled`, `Under review`.

### Последствия
- Хорошо: состояние ограничивает допустимые действия.
- Хорошо: переходы централизованы в сервисе сделок.
- Плохо: переходы нужно проверять бизнес-логикой и покрывать тестами; недопустимый переход отклоняется.
- Последствие: `Under review` не означает автоматическую санкцию; решение принимает модератор.

### Подтверждение
Модульные тесты проверяют допустимые и недопустимые переходы статусов. Отзыв возможен только после завершения; повторное завершение или отзыв по отменённой сделке отклоняются.

## Плюсы и минусы вариантов

### Состояния `Deal`
- Хорошо: жизненный цикл определён в SRS.
- Хорошо: статус влияет на отзывы и TC.
- Плохо: часть условий переходов зависит от решений заказчика.

### Состояния `Review`
- Хорошо: показывает публикацию отзыва.
- Плохо: точный жизненный цикл отзыва нужно сверять с SRS, а доступность отзыва определяется статусом сделки.

### Состояния запроса верификации
- Хорошо: простой цикл `Pending`, `Approved`, `Rejected`.
- Плохо: не влияет на сделки, отзывы и TC.
