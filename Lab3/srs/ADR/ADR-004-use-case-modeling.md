# ADR-004: Моделирование функций через Use Case

## Контекст и постановка задачи
SRS содержит функции для нескольких категорий пользователей и внешних сервисов. Нужно определить границы системы и инициаторов сценариев. Каким способом зафиксировать функции TrustRate и их участников?

## Драйверы решения
- Чёткие границы системы и внешние актёры.
- Понятность для заказчика и команды разработки.
- Явная связь функций с актёрами-инициаторами.
- Возможность детализировать сценарии отдельно от диаграммы.

## Рассмотренные варианты
- Use Case Diagram с отдельными спецификациями сценариев.
- Только текстовый перечень функциональных требований SRS.
- Пользовательские истории без диаграммы.

## Итог решения
Выбрана **Use Case Diagram** с актёрами «Гость», «Зарегистрированный пользователь», «Модератор», «Администратор», «Почтовый сервис» и «SMS-шлюз». Актёры находятся вне границы TrustRate, прецеденты — внутри. Подробные сценарии хранятся отдельно.

Связи на диаграмме: ассоциация показывает участие актёра; `include` — обязательное повторно используемое поведение; `extend` — условное расширение базового сценария; обобщение — специализацию при наличии общего поведения.

### Последствия
- Хорошо: диаграмма показывает границы системы и функции каждого актёра.
- Хорошо: внешние сервисы (email, SMS) явно отделены от пользовательских ролей.
- Плохо: диаграмма не показывает временной порядок шагов; он описывается потоками событий и диаграммами поведения.

### Подтверждение
На review проверять, что каждая функция SRS отражена прецедентом, у каждого прецедента есть инициатор-актёр, а связи `include` и `extend` используются по назначению.

## Плюсы и минусы вариантов

### Use Case Diagram со спецификациями
- Хорошо: наглядные границы и актёры.
- Хорошо: сценарии детализируются отдельно.
- Плохо: нужно поддерживать согласованность диаграммы и спецификаций.

### Текстовый перечень требований
- Хорошо: уже есть в SRS.
- Плохо: не видны границы системы и инициаторы сценариев.

### Пользовательские истории
- Хорошо: легко формулировать для отдельных ролей.
- Плохо: не показывают границы системы и связи между функциями.
