# Начало реализации основного функционала TrustRate

Реализация должна идти по утверждённому плану лабораторной №4 и приоритетам SRS. Данный список связывает UML-модели с первыми задачами реализации; он не заменяет согласованный календарный план.

| Порядок | Задача | Требования | Результат |
|---|---|---|---|
| 1 | Создать сущность Deal и перечисление DealStatus | REQ-FUNC-005 | Модель сделки со статусами SRS. |
| 2 | Реализовать создание и получение сделки | REQ-FUNC-005 | Пользователь создаёт и просматривает сделку. |
| 3 | Реализовать проверку участника и допустимости переходов | REQ-FUNC-005, SEC | Нельзя изменить чужую сделку или выполнить запрещённый переход. |
| 4 | Реализовать подтверждение завершения | REQ-FUNC-005 | Завершение только по согласованному правилу. |
| 5 | Реализовать Review и право на отзыв | REQ-FUNC-006–008 | Отзыв только участником завершённой сделки; дубликат запрещён. |
| 6 | Реализовать совместную публикацию | REQ-FUNC-019 | Публикация по правилу SRS. |
| 7 | Подключить расчёт рейтинга | REQ-FUNC-004 | Рейтинг пересчитывается по учитываемым отзывам. |
| 8 | Подключить операции TC к сделке | REQ-FUNC-009–011, 020–021 | Баланс и журнал обновляются атомарно. |

## Критерии готовности первой вертикали
- Сделка сохраняется в PostgreSQL.
- Статусы ограничены перечислением SRS.
- Изменять сделку может только её участник или уполномоченное лицо.
- Отзыв нельзя оставить по незавершённой сделке.
- Нельзя создать повторный отзыв одного участника по одной сделке.
- Недопустимые переходы возвращают контролируемую ошибку.
- Ключевые операции покрыты тестами.

## Открытые бизнес-правила
Нельзя придумывать вместо заказчика: точный способ подтверждения завершения сделки; обработку отсутствующего второго отзыва после окончания периода; суммы залога/начисления TC; числовые пороги антифрод-правил. До согласования эти пункты должны оставаться явно обозначенными как открытые.
